# sf-admin-notifications

Список уведомлений админки (решения C421, C331, C340–C342): последние в
панели уведомлений (sf-drawer справа) и вся история на своей странице
(`look="page"`).

```html
<sf-admin-notifications history-href="/panel/notifications"></sf-admin-notifications>
```

## Откуда данные

1. Порт, переданный `connectPort({port})`.
2. Иначе список просит порт у страницы событием `sf-host-port-request`
   (`owner: "admin-notifications"`).
3. Иначе берёт порт sf-admin-menu страницы: колокол меню и список читают
   одного хозяина.

Запросы порта `simai.admin-navigation-port` 1.1.0 и 1.2.0: `notifications.load
{cursor}` и `notifications.read {keys, all}`. После прочтения список просит
меню перечитать навигацию — число на колоколе следует за ним.

Без порта — настройка `items` (свойство или JSON в атрибуте): каждый
`{key, title, when, unread, href, icon, body, object, level, resolved, group,
group-label}`. `resolved` — `true` (проблема закрыта) или словами, как
закрыта («снова отвечает с 09:11»).

## Как выглядит

- По дням (`group-by="day"`): «Сегодня», «Вчера» — как назвал хозяин.
  Повторы одного объекта за день свёрнуты под тихой строкой-ссылкой
  «Ещё N по …» под текстом первого (`fold`). `group-by="object"` — группа на
  объект, ничего не свёрнуто.
- Значок уровня (ошибка, предупреждение, сведения, готово), заголовок —
  ссылка, «→ решено», когда хозяин закрыл проблему, строка объект · время.
  Уровень и «не прочитано» сказаны словами для экранного чтеца.
- «Новых: N» и «Прочитать все»; после «Прочитать все» фокус на счёте.
- Не загрузилось — sf-alert и «Повторить».

## Действия и события

- Действия: `refresh`, `read-all`, `read {keys}`, `add {item}`, `load-more`.
- События: `open {key, href}` (отменяемое), `read {keys}`, `read-all`,
  `load-more {cursor}`, `failed {reason}`.

## Издания порта

Список принимает издания 1.1.0 и 1.2.0 (`x-port.supports`). С 1.2.0
уведомление может сказать `object`, `level` (error, warning, info, success) и
`resolved` (`true` или словами): список читает их у хозяина, который заявил
1.2.0 или новее. У хозяина 1.1.0 этих полей нет (схема уведомления закрыта),
поэтому его уведомления рисуются как в 1.1.0: без свёртки по объекту, без
значка уровня и без «→ решено». Настройка `items` может нести все три поля.
