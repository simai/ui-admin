# Уведомления

Уведомления говорят человеку о том, что случилось без него: упал сервер,
закончилась проверка, пришёл заказ. Список устроен так, чтобы сотня похожих
сообщений не заслоняла одно важное.

## Дни и повторы

Список делится на дни, которые называет сервер: «Сегодня», «Вчера». Внутри
дня повторы одного объекта сворачиваются под строку «Ещё N по …»: первое
сообщение видно, остальные раскрываются по нажатию. Одна проблема — одна
запись: когда проблема решена, сервер помечает её `resolved`, и запись
кончается словами «→ решено».

:::diagram {engine=mermaid title="Как список собирает день"}
flowchart LR
  all["Уведомления дня"] --> by["По объекту"]
  by --> first["Первое видно"]
  by --> more["«Ещё N по …» — остальные"]
  first --> done{"Решено?"}
  done -- "да" --> mark["«→ решено»"]
:::

## Панель и страница истории

`look="panel"` — последние уведомления в панели справа: её открывает
колокол меню, внизу — «Вся история» и «Настройки уведомлений».
`look="page"` — страница истории на всю ширину, по частям с «Показать ещё».
На странице истории удобно группировать по объекту: `group-by="object"`.

:::example {id="components/admin-notifications-page" label="Страница истории по объектам"}
:::

## Откуда берутся

Список читает порт навигации (`notifications.load`) или берёт уведомления
из атрибута `items`, если сервер отдаёт их со страницей. Прочитанное список
отмечает сам: `notifications.read {keys}` для открытых и
`{all: true}` для «Прочитать все».

:::example {id="components/admin-notifications-port" label="Уведомления над портом" log="sf-admin-notifications-open sf-admin-notifications-read sf-admin-notifications-read-all"}
:::

## Колокол

Когда на странице есть `sf-admin-notifications` в виде панели внутри
`sf-drawer`, колокол меню открывает эту шторку, а список при открытии читает
порт заново. Без такой панели меню показывает свой список.
